# AI Assistant Landing Website

Landing page for the AI Assistant project with a **static** Notion-driven updates table.

## Features

- Landing page presenting the AI assistant vision for consulting businesses.
- Product goal documented in `PROJECT_GOAL.md`.
- Daily Notion sync to `public/updates.json` via GitHub Actions; the site only reads that file (suitable for **Render** static hosting — no GitHub Pages involved).
- Database rows use these properties (names are matched **case-insensitively**):
  - `Status`
  - `Changes`
  - `Time`
  - `Version`

## Setup

1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env` and set `NOTION_TOKEN` and `NOTION_DATABASE_ID`.
3. In Notion, share the **database** with your integration (Connections).
4. Optional local sync: `npm run sync:notion`
5. Run: `npm run dev` → open `http://localhost:3000`

## Static data source

- `public/updates.json` is generated by `scripts/sync-notion-data.js` and loaded as `GET /updates.json`.

## GitHub Actions (daily sync → commit)

- Workflow: `.github/workflows/sync-notion-data.yml`
- Schedule: once per day (`0 5 * * *`), plus manual **Run workflow**.
- Repository secrets: `NOTION_TOKEN`, `NOTION_DATABASE_ID` (must be a **database** UUID from the database URL, not a random page).

Behavior:

- **Commits only when** `public/updates.json` actually changes after a successful sync.
- **Zero rows** from Notion: the script does **not** overwrite `updates.json`, so there is nothing to commit (avoids wiping data with an empty file).
- Set `NOTION_FAIL_ON_EMPTY=true` in the workflow env if you want the job to **fail** when the database returns no rows (optional).

### If the workflow “doesn’t fetch” anything

1. Confirm the integration can see the database (share menu in Notion).
2. Use the **database** id (open the database as full page → copy link → 32-character id). A normal Notion **page** id will not work with `databases.query`.
3. Open the failed run → the sync step prints Notion API errors; the **Summary** lists property names on the first row so you can fix column names.

Example payload shape:

```json
{
  "generatedAt": "2026-04-24T05:00:00.000Z",
  "items": [
    {
      "status": "Done",
      "changes": "Improved docs module",
      "time": "2026-04-24",
      "version": "v1.2.0"
    }
  ]
}
```
